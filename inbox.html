Authentication

Letters City API uses API keys to authenticate requests. You can view and manage your API keys in the Developer Dashboard.

Keep Your API Keys Safe

Your API keys carry many privileges, so be sure to keep them secure! Do not share your secret API keys in publicly accessible areas such as GitHub, client-side code, etc.

Using API Keys

Include your API key in the Authorization header of all requests:

HTTP Header 
Authorization: Bearer YOUR_API_KEY

Example Request

cURL 
curl https://api.letterscity.com/v1/messages \
```

-H “Authorization: Bearer sk_live_4eC39HqLyjWDarjtT1zdp7dc”   
-H “Content-Type: application/json”
```

OAuth 2.0

For applications that need to access user data, we support OAuth 2.0 authentication. This allows users to authorize your application without sharing their credentials.

OAuth Flow

Rate Limits

To ensure fair usage and maintain service quality, we implement rate limiting on all API endpoints. Rate limits are applied per API key.

Plan Requests/Minute Requests/Day Burst Limit
Essentials 60 10,000 100
Signature 300 100,000 500
Enterprise 1,000 Unlimited 2,000

Rate Limit Headers

Every API response includes headers with your current rate limit status:

Response Headers 
X-RateLimit-Limit: 300
```

X-RateLimit-Remaining: 275
X-RateLimit-Reset: 1640995200
```

Rate Limit Best Practices

Implement exponential backoff when you receive a 429 response. Monitor the rate limit headers to avoid hitting limits. Cache responses when possible to reduce API calls.

Messages API

The Messages API allows you to send, retrieve, update, and delete email messages programmatically.

Endpoints

GET /messages

List all messages with optional filtering and pagination

GET /messages/:id

Retrieve a specific message by ID including full content and metadata

POST /messages

Send a new email message with optional attachments and scheduling

PUT /messages/:id

Update message properties like labels, read status, or folder

DELETE /messages/:id

Delete a message permanently or move to trash

Webhooks

Webhooks allow your application to receive real-time notifications when events occur in Letters City. Instead of polling the API, webhooks push data to your endpoint.

Setting Up Webhooks

  1. Create a webhook endpoint on your server that accepts POST requests
  2. Register your webhook URL in the Developer Dashboard
  3. Select the events you want to receive
  4. Verify webhook signatures to ensure authenticity

Available Events

message.received

Triggered when a new message arrives in the inbox

message.sent

Triggered when a message is successfully sent

message.read

Triggered when a recipient opens your message

message.deleted

Triggered when a message is deleted

Webhook Payload

JSON 
{
```

“id”: “evt_1234567890abcdef”,
“object”: “event”,
“type”: “message.received”,
“created”: 1640995200,
“data”: {
“object”: {
“id”: “msg_abcdef1234567890”,
“from”: {
“email”: “sender@example.com”,
“name”: “Jane Smith”
},
“subject”: “Important Update”,
“preview”: “Here’s the latest information…”
}
}
}
```

Verifying Signatures

Letters City signs webhook payloads with a secret key. Verify signatures to ensure requests come from Letters City:

Node.js 
const crypto = require('crypto');
```

function verifyWebhookSignature(payload, signature, secret) {
const hmac = crypto.createHmac(‘sha256’, secret);
const digest = hmac.update(payload).digest(‘hex’);

return crypto.timingSafeEqual(
Buffer.from(signature),
Buffer.from(digest)
);
}

// In your webhook endpoint
app.post(’/webhooks/letterscity’, (req, res) => {
const signature = req.headers[‘x-letterscity-signature’];
const isValid = verifyWebhookSignature(
JSON.stringify(req.body),
signature,
process.env.WEBHOOK_SECRET
);

if (!isValid) {
return res.status(401).send(‘Invalid signature’);
}

// Process webhook event
console.log(‘Webhook event:’, req.body.type);
res.status(200).send(‘OK’);
});
```

Search API

The Search API provides powerful full-text search capabilities across your messages, contacts, and attachments.

Basic Search

cURL 
curl "https://api.letterscity.com/v1/search?q=important+meeting" \
```

-H “Authorization: Bearer YOUR_API_KEY”
```

Advanced Search Operators

Use search operators to create precise queries:

  • from:email@example.com - Messages from specific sender
  • to:email@example.com - Messages to specific recipient
  • subject:"exact phrase" - Exact subject match
  • has:attachment - Messages with attachments
  • is:unread - Unread messages only
  • after:2024-01-01 - Messages after date
  • before:2024-12-31 - Messages before date
JavaScript 
const results = await client.search({
```

query: ‘from:boss@company.com has:attachment after:2024-01-01’,
limit: 50,
sort: ‘date’,
order: ‘desc’
});

console.log(`Found ${results.total} messages`);
results.items.forEach(message => {
console.log(`${message.subject} - ${message.from.email}`);
});
```

Error Handling

Letters City uses conventional HTTP response codes to indicate the success or failure of an API request.

HTTP Status Codes

Code Status Description
200 OK Request succeeded
201 Created Resource successfully created
400 Bad Request Invalid request parameters
401 Unauthorized Invalid or missing API key
403 Forbidden API key lacks required permissions
404 Not Found Resource doesn't exist
429 Too Many Requests Rate limit exceeded
500 Internal Server Error Something went wrong on our end

Error Response Format

JSON 
{
```

“error”: {
“type”: “invalid_request_error”,
“code”: “validation_error”,
“message”: “The ‘to’ field is required”,
“param”: “to”,
“request_id”: “req_1234567890abcdef”
}
}
```

Best Practices

Always check the HTTP status code. Handle rate limits with exponential backoff. Log request IDs for debugging. Use try-catch blocks in your code.
